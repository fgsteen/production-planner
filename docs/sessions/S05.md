- **Date:** 2026-10-04
- **Goal:** Stock per location, weekly truck cap, weekly machine plan (R42) and B→A transport breakdown (R43)

## Plan
- [x] Stock per storage location (pools) with pallet caps, initial stock
- [x] Weekly truck cap B → A
- [x] Weekly machine plan (R42)
- [x] Transport breakdown B → A (R43)
- [ ] Line clears and the priority-weights UI moved to S06 (scope agreed at the start)

## Log
- **Scope:** the full handoff plan was too big for one session. The user chose locations, trucks,
  R42 and R43, and moved line clears and the weights UI to later.
- **Answers (user):**
  - initial stock: editable, default zero;
  - trucks: a weekly cap;
  - demand: spreads by A's open days, not evenly.
- **LP** (`src/plan/lp.ts`): stock per storage pool (local per site, plus inbound at A),
  shipments per lane, draws at A and pallet caps. The truck limit is floored for weekday holidays,
  and there is a tiny shipping cost.
  [ADR 0005](../decisions/0005-storage-pools-and-weekly-trucks.md).
- **Finding:** with trucks modelled, the demo data was short 5.2M units at 5 trucks/week. The
  B-only products need ~221 pallets/week (~7.4 trucks). The user chose to raise the demo lane to
  **10 trucks/week**.
- **Demand:** `demandWeekWeights` counts the non-holiday days per week at the demand site. Demo
  2027 has 355 open days, so a normal week gets 7/355 of the total.
- **UI:**
  - Plan page: a weekly machine chart (stacked bars over available shifts) with a per-machine week
    table; a transport section with a units/pallets toggle and trucks used vs limit per week; a
    "Trucks B → A" summary tile.
  - Master data: a new **Initial stock** tab with pallets vs capacity.
- **Tests:**
  - LP: ships from B when trucks allow; makes the rest at A when the cap binds; storage limits
    building ahead; initial stock is used first.
  - Also: `truckLimit` and initial-stock validation.
  - e2e: R42/R43 views, the initial-stock editor; demand expectations updated for the new spread.
  - Checked in the browser pane, including phone width (no horizontal scroll).
- Lesson: Python on Windows wrote CRLF into files. Use `newline=''`.

## Outcome
Goal met. `npm test` is green: 5 tooling tests, typecheck, 60 unit tests and 19 e2e tests. The demo
plan solves in ~30–90 ms (4.9k columns, 2.7k rows) with no unmet demand. Trucks are at their limit
in 34 of 52 weeks, and B1 is ~4 % used, because the only goal is still least machine time. Not
done: line clears (MILP), priority weights (R22), the storage-level view (R37: data is in
`PlanResult.storage`, no UI yet).
