## Log
- **The user picked all four candidate goals for one session.** The user's answers:
  - **Pre-SMGs:**
    - regular products, flagged pre-SMG;
    - only a few SMGs use one, at 1:1;
    - arriving at B in the same week is fine;
    - B consumes them to make the SMG;
    - they share the B warehouse;
    - demo: 2 pre-SMGs, about 5 % of volume.
  - **Default priorities:** balanced load first.
  - **Grouping:** a group-by selector.
- **Demo data:**
  - P21 and P22 are pre-SMGs, used by P12 and P17 (both B-only). P22 can only be made at A4, so
    it is trucked A → B.
  - The A → B lane has 3 trucks × 30 pallets, weekdays.
  - Demand was cut by a fifth to about 34 M units, at the user's suggestion ("placeholder
    numbers").
- **MILP** ([ADR 0007](../decisions/0007-line-clear-milp-and-warm-start.md)):
  - weekly run binaries with a large clear per run;
  - a continuous small-clear overhead per lot;
  - four weighted goals.
  - HiGHS alone left millions of units unmet within 20 s, so I built a 3-stage warm start:
    relax and drop small runs, fix runs, then the MIP.
  - Bugs found while debugging:
    - solution arrays are views into Wasm memory and must be copied;
    - a fixed-run LP with no way to move work caused unmet demand in week 1;
    - LP re-solves warm-started from the old basis took 143 s, fixed with `clearSolver()`.
- **UI:**
  - **Plan page:**
    - priority sliders (debounced 500 ms, saved in settings);
    - summary with the busiest machine, large line clears, trucks per lane and the gap;
    - shifts table with group-by and line clear columns (large/small, hours);
    - warehouse panel (chart and table);
    - transport panels for both lanes.
  - **Master data:** pre-SMG checkbox and a "uses pre-SMG" select.
  - **Demand grid:** hides pre-SMGs; group-by shows read-only sums.
  - **Overview:** the map draws the A → B edge; the stats show truck capacity per lane.
  - Older saved files get the A → B lane added on load.
- **Tests:** unit tests for line clear time, campaign length vs weight, transport weight, the
  pre-SMG flow and its need for the lane, lane migration, and pre-SMG validation. I also added an
  e2e test for priorities, warehouses, group-by and the A → B lane.
- **Checked in the browser pane:**
  - the plan solves in 6.0 s with 0 unmet;
  - the warehouse chart renders;
  - group-by X gives the columns X K … X N;
  - moving a slider re-solves.

## Outcome
All four goals are built, and two parts are weak:
- **The line clear weight barely changes the demo plan.** There are about 1,040 large line clears
  at weight 4 and at weight 10. The heuristic start decides the plan, and the MIP doesn't improve
  it within 6 s. The unit test on a small case shows the weight working. The e2e test only checks
  that a weight change re-solves.
- **Group-by** is in the demand grid and the shifts table only, not in the weekly views or the
  transport tables.

Each solve now takes about 6 s instead of 120 ms.

`npm test`: green. 5 tooling tests, typecheck, 72 unit tests and 23 e2e tests.
